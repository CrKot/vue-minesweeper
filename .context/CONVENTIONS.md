# Соглашения проекта

## Код

- Не использовать односимвольные имена переменных в проектном коде.
- Не добавлять магические числа в игровую логику.
- Для размеров и настроек сложности использовать `GAME_BOARD` и `DIFFICULTY_CONFIG`.
- Для локальных числовых значений использовать именованные константы рядом с местом использования.
- Не трогать SVG/assets только ради устранения чисел: числа в SVG являются данными изображения.
- Использовать алиас `@/*` для импортов из `src`.
- Типы и интерфейсы импортировать через `import type { ... } from '@/types'`.
- Значения из `@/types` (например `DIFFICULTY_CONFIG`) — отдельным value-импортом.
- Сохранять текущий стиль Vue SFC: `<script setup lang="ts">`.
- Каждый компонент и composable — в отдельной папке с `index.ts`, который реэкспортирует публичный API.
- В `App.vue` и снаружи модуля — импорт из barrel: `@/components`, `@/composables`.

## Архитектура

- Игровую логику держать в `src/composables/useMinesweeper/useMinesweeper.ts`.
- UI-компоненты не должны сами расставлять мины, проверять win/lost или мутировать правила игры.
- `GameBoard` отвечает за сетку и координаты.
- `Cell` отвечает только за отображение одной клетки и пользовательские события.
- `App.vue` связывает composable и компоненты.

## Состояние игры

Текущие статусы:

- `idle`
- `playing`
- `won`
- `lost`

Первый клик:

- должен запускать игру;
- не должен попадать на мину;
- должен раскрывать выбранную клетку.

Флаги:

- работают только при `playing`;
- не ставятся на открытые клетки;
- влияют на `flagsLeft`.

Таймер:

- стартует с игры;
- сбрасывается при reset;
- останавливается при win/lost;
- очищается при unmount.

Открытие пустых областей:

- не использовать рекурсию для flood fill;
- использовать очередь или стек, чтобы не упираться в call stack на больших полях.

## CSS/UI

- Глобальный CSS держать минимальным.
- Компонентные стили оставлять scoped.
- Широкое hard-поле должно оставаться доступным на узком экране через горизонтальный скролл.
- Не вводить глобальные классы с общими именами, которые могут конфликтовать с компонентами.
- Цвета ячеек, чисел и статус-бара держать в CSS-переменных в `src/style.css`.
- Ячейки должны оставаться доступными с клавиатуры.

## Проверки качества

Перед финальным ответом после правок:

```bash
npm test
npm run build
```

Если одна из команд не проходит, сначала исправить проблему или явно объяснить, почему не получилось.
